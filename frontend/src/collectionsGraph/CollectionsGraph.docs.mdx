## When to use

`CollectionsGraph` renders the Graph view of `CollectionsPage` (`?page=collections` with the
view toggle on Graph). It consumes a `GraphModel` built by `buildGraphModel` from
`GET /api/collections/graph?order=`; the page intersects the payload with the filtered list ids,
so Type / Mine / Owner filters reach the graph while search only highlights matches. The
collection-page graph dialog (#1630) reuses this component with a different model builder.

## Implementation guidance

- Physics and rendering port the locked prototype design (#1627): soft links, firm collisions,
  charge on hub/collections/categories only, rAF-coalesced batched canvas drawing, viewport
  culling, label cap, and a lazily rebuilt hit-test quadtree.
- The view fits once after synchronous pre-ticks per model build; resize and view switches
  redraw without refitting — the outlined **Fit graph** toolbar button refits explicitly.
  Optional `fitOnRebuild` also refits (animated) when a rebuilt model arrives under a kept
  transform — used by `CollectionGraphDialog`, not the page graph.
- The stats caption and controls (order toggle, Shared only, **Fit graph**) live in a toolbar
  row above the `position: relative` canvas wrapper — nothing overlays the drawing; legend,
  empty state and tooltip stay inside the wrapper, and the ResizeObserver / tooltip clamp
  measure it.
- The legend is always open (#1656) — a "Node size reflects image count" subtitle under the
  caption — and is order- and variant-aware via `legendVariant`: the default
  `'page'` labels the hub "Collections hub (centre)" and the collection rows "Sequence
  collection" / "Synchronized collection"; `'collection'` (the dialog) uses "This
  collection (centre)", "Related sequence collection" / "Related synchronized collection",
  always shows the image/shared-image rows (member images are the
  spokes at every order), and shows the related-collection/synchronized rows only at
  order ≥ 2. On the page, image/shared-image rows appear at order ≥ 2; the category row
  appears at order ≥ 3 in both variants. A bottom-right hint reads "Scroll or pinch to
  zoom, and drag to pan."
- `sharedOnly` hides single-collection images from drawing and hit testing but keeps them in
  the simulation; category nodes are never hidden.
- Node clicks: collections call `onOpenCollection`, images call `onOpenImage(imageId)` — the
  page fetches the record and takes the normal `?image={id}` viewer path; hub and category
  clicks are inert.

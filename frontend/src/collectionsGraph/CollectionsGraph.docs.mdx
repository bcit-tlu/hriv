## When to use

`CollectionsGraph` renders the Graph view of `CollectionsPage` (`?page=collections` with the
view toggle on Graph). It consumes a `GraphModel` built by `buildGraphModel` from
`GET /api/collections/graph?order=`; the page intersects the payload with the filtered list ids,
so Type / Mine / Owner filters reach the graph while search only highlights matches. The
collection-page graph dialog (#1630) reuses this component with a different model builder.

## Implementation guidance

- Physics and rendering port the locked prototype design (#1627): soft links, firm collisions,
  charge on hub/collections/categories only, rAF-coalesced batched canvas drawing, viewport
  culling, label cap, and a lazily rebuilt hit-test quadtree.
- The view fits once after synchronous pre-ticks per model build; resize and view switches
  redraw without refitting — Fit is explicit.
- `sharedOnly` hides single-collection images from drawing and hit testing but keeps them in
  the simulation; category nodes are never hidden.
- Node clicks: collections call `onOpenCollection`, images call `onOpenImage(imageId)` — the
  page fetches the record and takes the normal `?image={id}` viewer path; hub and category
  clicks are inert.

## When to use

Use `CollectionCard` inside the collections-page grids (`CollectionsPage`) and the Browse tile
grid to represent one `CollectionSummary`. Clicking the card body opens the collection
(`?collection={id}`); the overlay icons call `onMove` / `onTransfer` and the metadata pencil calls
`onEdit`. There is no card-level delete — Delete Collection lives inside the edit dialog (#1554).

## Implementation guidance

- The cover is rendered through `RenewingThumbnail` with a collection-specific renewer, so an
  expired thumbnail token is refreshed via `GET /api/collections/{id}` rather than the image route.
- The type chip sits in the cover overlay beside the action icons — the same `top: 4, right: 4`
  white-on-`rgba(0,0,0,0.25)` scrim convention as `CategoryTile` (#1554). The visibility chip lives
  in the metadata area and reuses the
  category restriction palette — `Restricted` borrows the group-chip colours, `Public` is neutral
  outlined, `Private` uses the muted visibility grey.
- Action icons are a UX gate only: Owners renders when `permissions.canTransfer` is true **and**
  `onTransfer` is supplied, Edit when `permissions.canEdit` **and** `onEdit`, and Move whenever
  `onMove` is supplied (filing is curatorial — the caller role-gates to admin/instructor). The
  backend re-checks authority on
  every call. Overlay clicks stop propagation so they never open the card.
- Without a cover the card shows the collections icon on a primary-coloured block.

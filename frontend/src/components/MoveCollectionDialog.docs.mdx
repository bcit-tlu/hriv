## When to use

The dialog opens from the **Move** affordance on a collection Browse tile or a Collections
page card. Filing is curatorial, so the affordance is gated on the admin/instructor role
rather than `permissions.canEdit`.

## Implementation guidance

- **Destination picker.** Reuses `CategoryPickerSelect`; _None. Access in Manage > Collections._ unfiles a
  collection, while any category files it onto Browse.
- **No-op protection.** The picker preselects the collection's current category on
  open; `useCategoryActions` treats an unchanged destination as a close, not a POST.
- **Versioned write.** `POST /api/collections/{id}/move` carries `version`; on a 409
  the conflict's authoritative record replaces the dialog's collection so a retry
  posts the fresh version.
- **Undo.** The success snackbar's Undo re-posts the previous category with the move
  response's (bumped) version.
- **Private collections.** Filing a private collection shows a warning (not a block):
  “This collection is private. Students will not be able to see the images in this
  collection.”
- **Unfiling.** Removing a collection from Browse reports `Removed “<name>” from Browse`;
  Undo restores its previous category.

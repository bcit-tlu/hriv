## When to use

`ImageViewer` exposes two slots — `viewportControl` (an OSD toolbar control) and
`viewportOverlay` (portaled inside the viewport). `CollectionImageDetails` holds the shared
open state, focus ref and lazy source-info fetch so the
`<CollectionImageDetailsTrigger/>` and `<CollectionImageDetailsDrawer/>` can mount in those
separate slots without prop drilling. The collection viewers wrap each `ImageViewer` in a
provider — one per synchronized pane — so every pane's drawer opens independently and fetches
source info only when first opened. Wrap the provider in a `key={image.id}` (sequence viewer)
or give each pane its own instance (synchronized viewer) so a member change resets the drawer
closed. The story renders two fake panes to show the independence; the drawer itself is
`ImageDetailsDrawer`.

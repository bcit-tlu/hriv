# SynchronizedCollectionViewer

Two to four read-only OpenSeadragon panes for `synchronized` collections, mounted by
`CollectionsPage` under the shared detail header (#1417, #1561).

## Layout

- **Up to four visible members** render as panes — a left/right row for two, a 2×2 grid for
  three or four — each a read-only `ImageViewer` (`canEditContent={false}`, stored
  annotations/locked overlays/measurement from `metadataExtra` pass through without edit
  callbacks). A member count above the pane cap produces a "Showing _N_ of _M_" note.
- Each pane has a caption with the member name (plus an _inactive_ marker) and an **Open image**
  action that navigates to the regular `?image={id}` view where annotations can be edited.
- A **pin** button sits at the top-right of each pane's viewport (#1564). Panes start pinned
  (linked); unpinning detaches that pane so it pans/zooms/rotates independently, and the filled
  vs outlined pin icon plus the button's pressed state show which panes are linked.
- Fewer than two visible members shows a fallback alert with the ordered member list and
  per-row **Open image** links. Members whose tiles fail mid-session are skipped; if the failures
  leave fewer than two, the fallback explains that the images could not be loaded.

## Linked navigation

- Pan, zoom and rotation on any viewer mirror onto every other pane immediately (no spring lag)
  via raw `viewport-change` events exposed by `ImageViewer`'s `onViewerReady` prop. A re-entrancy
  guard prevents feedback loops, and programmatic writes (reset, follower updates) never lead
  the sync.
- The panes keep an armed **baseline** — each opened pane's viewport snapshot — so images
  aligned around different highlights stay aligned: a leader's displacement from its baseline
  (multiplicative zoom ratio, additive centre and rotation deltas) is applied to every
  follower's baseline. For two panes this is the pairwise offset the viewer originally kept.
- **Pinning is per pane** (#1564). An unpinned leader does not move anyone, and unpinned panes
  do not follow a pinned leader — so a subset of the grid can stay linked while one pane is
  inspected on its own. Re-pinning re-captures the baselines at the current positions instead
  of snapping the pane back to where it left, which is also how a new alignment is composed.

## Persisted view

`collection.viewport_state` maps `"<image_id>"` to `{ zoom, x, y, rotation }` — each pane's
absolute position. Entries that don't match the shape are ignored.

- **Save view** (editors only) writes every pane's current viewport through
  `PUT /api/collections/{id}/viewport` (whole-replace, optimistic-concurrency `version`), so the
  saved layout restores exactly on reload and through `?collection={id}` share links.
- **Reset view** (everyone) re-applies the saved positions — or each viewer's home when nothing
  is saved — then re-arms the baselines.
- Non-editors receive the saved view on load and may pan/zoom freely without persisting anything.

## Orientation

In `portrait` orientation a full-panel hint asks the user to rotate to landscape. The viewers
stay mounted underneath the overlay so rotating back restores the exact view rather than
re-opening the images.

## Stories

- **Basic** — two panes, linked, editor toolbar.
- **Larger Set** — four members in the 2×2 grid.
- **Portrait Hint** — the orientation overlay (matchMedia is stubbed).
- **Read-Only Member** — no Save control without `can_edit`.
- **Too Few Images** — the fallback state with the member list.

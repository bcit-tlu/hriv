## When to use

Use `ImageCollectionsList` in the image viewer metadata row to tell a viewer which collections the
current image is part of (#1586). It is purely informational — it does not add or remove membership.

The names passed in are already **visibility-filtered server-side**: the
`GET /api/images/{id}/collections` endpoint only returns collections the caller may view, so a
student never sees a private or restricted collection they could not open.

## Interactive example

`Basic` exposes the `names` and `limit` controls. With more than `limit` names (default 3), the
extras collapse behind a "… and N more" link that expands them inline.

## Implementation guidance

- Renders nothing when `names` is empty — the caller can mount it unconditionally.
- The label pluralizes ("Collection" vs "Collections"), matching the Program/Group metadata rows.
- Styling matches the viewer metadata area: `body2`, `text.secondary`, inline `component="span"`.
- In the viewer, pass `key={imageId}` so the expand toggle resets when the user switches images.
- Names are plain text today; linking each name to open its collection is an easy future addition.
